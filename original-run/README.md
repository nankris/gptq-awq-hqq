# Three 4-bit recipes, one model (GPTQ vs AWQ vs HQQ on Qwen3-8B)

Question: How do GPTQ (gptqmodel), AWQ (llm-compressor or autoawq), and HQQ compare with BF16 for Qwen/Qwen3-8B?

Hypothesis: each 4-bit recipe loses at most 1 percentage point of accuracy versus BF16; HQQ quantizes fastest and needs no calibration data.

## Preregistered setup and decision rule
Use Qwen/Qwen3-8B unless tool support prevents it, in which case document the switch to Llama-3.1-8B-Instruct. Use a single L4 if feasible. All methods use the same tokenizer and fixed evaluation data: 200 MMLU test items and 200 ARC-Challenge test items, selected with seed 44. Report each dataset and the combined 400-item accuracy, with 95% paired item bootstrap CIs (10,000 resamples, seed 44). Score answer options by conditional log likelihood with a fixed zero-shot prompt, with thinking disabled. No test items enter calibration. WikiText-2 raw test perplexity uses nonoverlapping 512-token blocks (last incomplete block omitted). Calibration, if needed, uses 128 sequences of 512 tokens from WikiText-2 raw train, seed 44, identically for GPTQ and AWQ. HQQ uses no calibration.

Accuracy hypothesis is PROVEN only if all three paired accuracy-difference CIs have lower bounds >= -1 percentage point; DISPROVEN if any has upper bound < -1; otherwise INCONCLUSIVE. The full hypothesis is PROVEN only if the accuracy condition passes and HQQ's measured quantization wall time is strictly lower than both other successful methods with no calibration. A missing method makes the full hypothesis INCONCLUSIVE unless already disproven. Report component conclusions separately. Timing is a single run, descriptive, without a timing CI. Fixed 400-item sample has limited power for a one-point equivalence claim.

Measure quantization wall time (model loaded through quantization complete; downloads excluded where possible and boundaries explicitly logged), serialized model bytes, peak allocated CUDA memory separately for quantization and evaluation, batch-1 greedy generation tokens/s (32-token prompt, 128 new tokens, warmup + 3 repetitions), WikiText-2 perplexity, and accuracy. Record actual deviations explicitly; do not substitute downloaded prequantized models for measured quantization. Allow at most 20 minutes of installation fixes per failing library, then record failure and continue.

## Completed results
All four methods completed on the original Qwen3-8B checkpoint; no substitution. BF16 / GPTQ / AWQ / HQQ combined accuracies: 79.25 / 77.50 / 77.50 / 76.75%. HQQ took 41.176 seconds (0.69 minutes), compared with GPTQ 5.24 and AWQ 13.99 minutes. Its paired accuracy change was −2.50 points [95% CI −5.25, +0.25]. Full hypothesis and accuracy component: **INCONCLUSIVE**. HQQ was descriptively fastest with no calibration, but the one-point accuracy guarantee was not established for any recipe. See writeup.md and results/summary.json for all estimates.

**AWQ inference limitation:** compressed-tensors reloaded its packed 4-bit checkpoint and decompressed it into BF16 ordinary Linear modules for inference (16.54 billion resident parameter bytes). The reported AWQ perplexity/accuracy evaluate reconstructed quantized weights, while its throughput and evaluation peak VRAM describe this decompressed runtime. This is not an optimized packed-AWQ inference comparison. HQQ uses native HQQLinear and GPTQ uses GPTQModel TorchLinear. The original AWQ OOM and GPTQ offloaded meta-tensor transfer failure were recovered by fresh-process evaluation of saved checkpoints; no quantization timings were repeated.
